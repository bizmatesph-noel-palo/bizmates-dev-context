# [ASC-269]
Refund Row Missing from Monthly Rate Calculation CSV — B2C Monthly Plan

[Story]
A refund executed in April 2026 for a B2C monthly plan (`月15回プラン`) is completely missing from the April Monthly Rate Calculation CSV report. While a refund executed on the exact same date for a daily plan charge appears correctly in the Daily Rate Calculation CSV, the monthly plan pipeline fails to generate the row. This indicates an issue unique to how the monthly calculation engine filters or handles refund transactions.

[Precondition]

* **Student ID:** 238716
* **Target Charge ID:** 3046071
* **Plan Type:** 月15回プラン (15 lessons / month, B2C)
* **Refund Execution Date:** 2026-04-20
* **Refund Amount:** -13,365

[Steps]

1. Issue a refund transaction of -13,365 against `charge_id 3046071` on 2026-04-20.
2. Generate the April monthly calculation report (target_ym=202604).
3. Search the generated `MonthlyRateCalculation` CSV output for `student_id: 238716`.

[Expected]
File: 202604_03_MonthlyRateCalculation([YYYYMMDD]).csv

```csv
target_ym,student_id,department_id,order_no,charge_id,total,number_of_carried_over_lessons,number_of_lessons_taken,number_of_expired_lessons,number_of_remaining_lessons,paid_price
202604,238716,,,3046071,,,,,,-13365

```

*Note: A dedicated refund row must appear with the `paid_price` set to `-13365` and all ticket count columns left completely blank.*

[Actual]
File: 202604_03_MonthlyRateCalculation([YYYYMMDD]).csv
*(Bug: No row exists for this refund transaction in the file)*

[Comparison Summary]

| Target Report File | charge_id | Expected Layout | Actual Status |
| --- | --- | --- | --- |
| **03_MonthlyRateCalculation** | 3046071 | Row present, `paid_price = -13365`, ticket counts blank | **Row Omitted / Missing** |

[Acceptance Criteria]
* Refund records for monthly plans must be processed and output in the `MonthlyRateCalculation` CSV, matching the successful behavior of the daily calculation engine.
* The refund row must display the correct negative transaction amount in the `paid_price` column while leaving the ticket-counting columns blank.
* Refund data must not be dropped or filtered out during intermediate data extraction stages.
