# [ASC-244]
Refund Record Displays Incorrect Charge ID — Must Match Refund Transaction ID

[Story]
When a refund is processed, the monthly report was incorrectly using the original purchase's charge_id for the refund row instead of the unique charge_id generated for the refund transaction itself. The accounting team requires the monthly report to match the daily lesson report, where the refund is identified by its own distinct ID.

[Precondition]

* **Student ID:** 289962
* **Department ID:** 11034
* **Plan Type:** 月15回プラン (15 lessons / month, B2B2C)
* **Original Charge (2970434):** Price: 7,425 | Period: 2026-02-26 to 2026-02-26
* **Refund Transaction (2971875):** Created to refund the above | Price: -7,425 | Executed: 2026-02-26

[Steps]

1. Execute a refund for student 289962 against charge 2970434.
2. Generate the February monthly report (target_ym=202602) via the 202603 batch.
3. Locate the refund row and the original charge row for student 289962.

[Expected]
**① February Data : 202602 CSV**
File: 202602_03_MonthlyRateCalculation(YYYYMMDD).csv

```csv
target_ym,student_id,department_id,order_no,charge_id,total,number_of_carried_over_lessons,number_of_lessons_taken,number_of_expired_lessons,number_of_remaining_lessons,paid_price
202602,289962,11034,,2970434,15,0,0,0,15,0
202602,289962,11034,,2971875,,,,,,-7425
```

*Note: The refund row must display the Refund Transaction's own charge_id (2971875), NOT the original charge_id (2970434). Ticket count columns must be blank for refund rows.*

[Actual — Before Fix]
**① February Data : 202602 CSV**
File: 202602_03_MonthlyRateCalculation(YYYYMMDD).csv

```csv
target_ym,student_id,department_id,order_no,charge_id,total,number_of_carried_over_lessons,number_of_lessons_taken,number_of_expired_lessons,number_of_remaining_lessons,paid_price
202602,289962,11034,,2970434,,,,,,-7425
202602,289962,11034,,2970434,15,0,0,0,15,0
```

*Bug: Both rows displayed the original charge_id (2970434). The refund transaction ID (2971875) was being overwritten.*

[Actual — After Fix]
**① February Data : 202602 CSV**
File: 202602_03_MonthlyRateCalculation(YYYYMMDD).csv

```csv
target_ym,student_id,department_id,order_no,charge_id,total,number_of_carried_over_lessons,number_of_lessons_taken,number_of_expired_lessons,number_of_remaining_lessons,paid_price
202602,289962,11034,,2970434,15,0,0,0,15,0
202602,289962,11034,,2971875,,,,,,-7425
```

*Fix confirmed: The refund row now correctly displays charge_id 2971875 (the refund transaction's own ID).*

[Acceptance Criteria]

* Refund records in the monthly report must display their own created charge_id (the Refund Transaction ID).
* The report mapping logic must prevent the original charge_id from masking the refund transaction ID.
* Refund rows must have blank ticket count columns (total, carried_over, taken, expired, remaining) with only paid_price populated as a negative value.
