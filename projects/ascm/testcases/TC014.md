# [ASC-211]
B2B Order Transition — Last Charge of Order Incorrectly Treated as 60-Day Valid

[Story]
When a student has multiple charges under the same order, the last charge before transitioning to a new order is incorrectly treated as a 60-day valid ticket. Since the next charge belongs to a different order, the previous charge's remaining lessons should expire at the end of that month. However, the system currently carries them over into active availability as if they are still valid, resulting in incorrect expired, remaining, and paid_price values in the monthly report.

[Precondition]
Student 181524 has the following charges (plan: 8 lessons):

* **Charge No1 (2768090):** Order 10021996 | 2025-11-11 to 2025-12-10
* **Charge No2 (2768091):** Order 10021996 | 2025-12-11 to 2026-01-10 *(Last charge of this order, unused in January)*
* **Charge No3 (2880531):** Order 10021998 | 2026-01-11 to 2026-02-10 *(New order string)*

[Steps]
Generate the January monthly report (target_ym=202601) via the 202602 batch execution cycle.

[Expected]
File: 202601_03_MonthlyRateCalculation(20260201).csv

```csv
target_ym,student_id,department_id,order_no,charge_id,total,number_of_carried_over_lessons,number_of_lessons_taken,number_of_expired_lessons,number_of_remaining_lessons,paid_price
202601,181524,11884,10021996,2768090,8,2,1,1,0,2640
202601,181524,11884,10021996,2768091,8,8,0,8,0,10560
202601,181524,11884,10021998,2880531,8,0,3,0,5,3960
```

*Note: The key assertion is charge 2768091 (last charge of order 10021996) must expire all 8 tickets with paid_price=10560. It must NOT carry over to the next month.*

[Actual — Before Fix]
File: 202601_03_MonthlyRateCalculation(20260201).csv

```csv
target_ym,student_id,department_id,order_no,charge_id,total,number_of_carried_over_lessons,number_of_lessons_taken,number_of_expired_lessons,number_of_remaining_lessons,paid_price
202601,181524,11884,10021996,2768090,8,3,1,2,0,3960
202601,181524,11884,10021996,2768091,8,8,0,0,8,0
202601,181524,11884,10021998,2880531,8,0,3,0,5,3960
```

*Bug: Charge 2768091 shows expired=0, remaining=8, paid=0 — the system incorrectly treats it as a 60-day valid ticket instead of expiring it at the order boundary.*

[Comparison Summary]

**Charge 2768091 (Order 10021996 - Last Charge):**

* **number_of_expired_lessons:** Expected 8 | Actual (before fix) 0
* **number_of_remaining_lessons:** Expected 0 | Actual (before fix) 8
* **paid_price:** Expected 10560 | Actual (before fix) 0

[Acceptance Criteria]

* When a student has multiple charges under the same order, the final charge window before transitioning to a new order contract must expire cleanly at the end of the month boundary.
* It must not carry over to subsequent months or be extended via standard 60-day validation parameters.
* The remaining tickets for `charge_id 2768091` must show as completely expired with a final generated `paid_price` of 10,560.
