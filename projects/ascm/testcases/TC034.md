# [ASC-297]
Missing Row When Student Requests REST Status Scheduled for the Following Month

[Story]
When a student submits a REST (休会 / pause account) request that is scheduled to take effect in the following month, the active charge row for the current reporting month goes completely missing from the `MonthlyRateCalculation` CSV output. Because this row is incorrectly suppressed or filtered out by the system, unspent active tickets fail to be tracked properly during the pre-REST transition period.

[Precondition]
* **Student ID:** S00000287011
* **Plan:** 毎月15回まとめてレッスンプラン (15 lesson plan, Base Price: ¥14,850)
* **Relevant Charge History Sequence:**
* **Charge 3036695:** 2026-04-10 – 2026-05-09 (0 taken, 15 should expire)
* **Charge 3071673:** 2026-05-10 – 2026-06-09 *(Target Missing Row)*
* **Charge 3107436:** 2026-06-10 – 2026-07-09

* **REST Request Log:**
* Submitted on: `2026-06-10 17:22`
* Target Contract End Date: `2026-07-10`
* Target Expiry Date: `2026-07-09`
* Status: `cancel_status = TRUE`


[Steps]
1. Log a future-dated REST request for Student 287011 during the active processing window.
2. Generate the May monthly calculation report (`target_ym=202605`) via the 20260601 batch sequence.
3. Inspect the final output generated on 6/11 for student_id "287011".
