# [ASC-264]
Charge Row Processing Failure at Period Boundaries (Zipan Missing Row & Bizmates Broken Carry-Over Cascade)

## [Story]
A systemic data-filtering regression occurs for charges whose `end_date` or initialization spans across reporting period boundaries. This defect exhibits two distinct behaviors: rows are completely omitted from the summary report, or the `number_of_carried_over_lessons` balance is wiped to `0` in the following month. The missing historical data causes analytical window functions (like `LAG` on a previous month's remaining value) to return a null or default `0` state, breaking calculation workflows for both Zipan and Bizmates platforms.

## [Precondition]
* **Systemic Trigger:** Charges ending or initializing near the period boundaries are dropped during intermediate CTE processing (`FilteredUsage` script filters).
* **Zipan Pricing Basis:** 10 lessons/month plan (Remaining units expire immediately at contract end date).
* **Bizmates Pricing Basis:** 月8回プラン B2B (Fixed unit rate calculation basis: ¥1,320 per lesson, total charge value: 10,560).

### [Comparison & Root Cause Analysis for Devin AI]
* **March Report Anomaly:** `charge_id 2880533` dropped out completely during compilation because its activation window intersected poorly with boundary parameters.
* **April Report Anomaly:** `number_of_carried_over_lessons` registers as `0` instead of `8`.
* **Root Cause Hook:** Because the March row was missing, analytical operations executing a `LAG` or lookup fetch on `remaining_before` find no antecedent historical row structure. The query baseline falls back to 0, wiping out the carry-over metric.

### [Acceptance Criteria]
1. Adjust the boundary logic in the `FilteredUsage` CTE block to prevent the exclusion of charge sequences ending or starting on data compilation borders.
2. Ensure that zero-usage charges (like Bizmates 2880533 in March) print an entry row to the output sheet so subsequent analytics can pull carry-over parameters via sequential data hooks.
3. Verify that `carried_over` parameters match the explicit calculation framework when data cascades down the ledger across consecutive processing terms.
